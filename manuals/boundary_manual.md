# 工作边界编码手册（S17-T2，D17-5；v1.1 冻结版，D29）

本手册用于判断编码智能体会话中的"工作片段"与开发者心目中的"一项工作"是否一致。工作片段是开发者的一条请求（连同并入的接续消息）及智能体随后的全部动作。编码人以**事后回看自己工作记录的开发者**的身份判断：依据请求原文、会话前后文、所改文件与任务书，判断这些改动在开发者看来是几项工作、从哪里开始、到哪里结束。

证据包不含任何提交信息，也不应推测改动是如何提交的。判断只关心"工作"本身。

## 1 什么是一项工作

一项工作是开发者会**作为一个整体验收或退回**的一次改动，有一个明确的目标：实现一个功能、修一个缺陷、做一处界面或文案调整、完成任务书中的一个条目。判别问题是："如果只接受其中一部分、退回另一部分，开发者会觉得合理吗？"合理，就是两项工作；不合理，就是一项。

- 任务书中编号不同的条目（如 M3-T1 与 M3-T2）是不同的工作，即使在同一条请求中连续执行。
- 同一目标的返工、修正、微调（"还是不对""再小一点""这里留白太多"）与原工作是同一项工作，前提是目标没有变。
- 目标变了就是新工作，即使改的是同一个文件。
- 纯粹的探索、答疑、部署操作不计为工作项；本手册只判断改了代码的片段。

## 2 问题与填写

编码表为随材料发给你的 xlsx 录入表（"录入"工作表），列固定为：

```
packet,prev_same,next_same,n_works,groups,cross,conf,note
```

两名编码人各自独立填写，不一致的片段由不参与编码的裁决人裁定（裁决人看不到答案来自谁）。先做前 5 个；对条文有疑问当天微信问作者，作者只解释条文，不回答某个片段应填什么。证据包含商业信息，不外传，完成后删除本地副本。

**Q1 prev_same：与前一代码修改片段（◀）是否同一项工作。** 1 = 是（本片段在继续、修正或完善前一片段的同一目标），0 = 否，NA = 证据包写明没有前一代码修改片段。只看 ◀ 所指的那一个片段，中间不改代码的消息不影响判断。

**Q2 next_same：与后一代码修改片段（▶）是否同一项工作。** 取值同上。

**Q3 n_works 与 groups：本片段含几项可独立验收的工作。** 请求里列了几件彼此独立、可以分别验收的事（如"1、……2、……"且目标不同），或一次执行了任务书的多个条目，就填相应的数目；只做一件事填 1。n_works > 1 时，在 groups 中按第 3 节的文件编号分组，组与组之间用 `|`，组内用 `+`，如 `F1+F2|F3`。一个文件同时服务多项工作时，归到它主要服务的那一项。若几项工作改的是同一批文件、无法按文件分开，groups 填 `不可分`。n_works = 1 时 groups 留空。

**Q4 cross：是否延续其他会话中的某一片段。** 第 7 节列出其他会话中此前 48 小时内改过相同文件的片段（X1–X5）。若本片段继续的正是其中某一片段的同一目标，填其编号；否则填 `无`。只改到相同的公共文件（如样式表、公共页头）不足以判为延续，要看目标是否相同。

**Q5 conf：把握。** 1 = 猜测，2 = 较有把握，3 = 证据明确。

**note：** 一句话说明判断依据，尤其是填 0/1 有犹豫、或 n_works > 1 时。

## 3 判断要点与例子

- "手机端布局混乱，处理一下"之后接"手机端这个位置 logo 小一点"：同一目标（手机端布局）的细化，Q1 = 1。
- "执行 M4 任务书"且片段内依次完成了 T1–T5：n_works = 5，按各条目涉及的文件分组。
- "1、首页加分页；2、详情页加头图；3、把客服电话改成可拨号"：三个独立目标，n_works = 3。
- 前一片段"实现登录接口"，本片段"登录页样式调整"：目标不同，Q1 = 0，即使都属于"登录"主题。
- 本片段是会话第一条消息，写"继续上次的资讯列表页"，X2 的请求正是资讯列表页：Q4 = X2。
- 拿不准时按请求原文判断，不要因为改了相同文件就判为同一工作，也不要因为请求很短就判为新工作。
